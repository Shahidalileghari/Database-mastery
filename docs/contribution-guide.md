# Contribution Guide

1. Open an issue describing the learning topic, bug, or improvement.
2. Keep SQL examples self-contained and specify the target PostgreSQL version when relevant.
3. Include expected output or explain what a query demonstrates.
4. Avoid secrets, real personal data, and destructive commands without explicit warnings.
5. Test scripts in a disposable local database before submitting a pull request.
6. Prefer small, focused commits and update the README or roadmap when scope changes.
